# Etch website

Product and introductory documentation source for
<https://www.rm-industries.com/etch/>. The site is an Astro project generated by
Forge inside the Etch repository. Node/npm dependencies and their lockfile live
here; Etch's Python-only runtime does not import or install them.

## Work locally

Use Node 22.22.2+, 24.x or 26.x within the supported package engine ranges and npm
10.9.x or 11.x. From the repository root:

```sh
npm ci --prefix website
npm run dev --prefix website
npm run quality:core --prefix website
npm run test:e2e --prefix website
npm run lighthouse:ci --prefix website
```

Browser checks require Playwright browsers. Install them from this directory with
`npx playwright install`; Linux CI uses `--with-deps`. Core quality includes
formatting, linting, spelling, unused-code checks, types, unit coverage, production
build and artifact validation. Deployment smoke checks run after Pages deployment.

Public Markdown guides live in the repository’s `docs/guides/` directory. Only
that directory is published as the `docs` collection at `/etch/docs/`; the other
files in root `docs/` remain repository documentation. Fenced code blocks use
shared terminal styling and Catppuccin syntax colors in both themes.

The landing/about pages live in `src/pages/`,
and shared identity/navigation in `src/config/site.ts`. Introductory pages link to
the maintained repository documentation. The complete user guide and migration
material remain tracked in Etch #29.

## Nested generation provenance

Generated with Forge commit `f4382661fb37cce2da2eaac9959562dff338d746`, including
Forge #210 and #211. Its package version is still 1.0.2; the published npm 1.0.2
initializer does not contain `--repository-root`. To reproduce the scaffold in a
fresh checkout, build the pinned Forge source with `npm ci --ignore-scripts` and
`npm run build --workspace @rm-industries/create-forge`, then run its built CLI:

```sh
node /path/to/forge/packages/create-forge/dist/index.mjs website \
  --repository-root . --yes --no-install --no-git \
  --name etch-website --site-name Etch --author 'RM Industries' \
  --description 'Make your environment yours. A portable, declarative environment manager.' \
  --url https://www.rm-industries.com/etch/ --repository rm-industries/etch
```

Do not regenerate over a customized website. Review changes in a separate checkout.
This consumer uses `./.github/actions/setup-project` for local-action references
and removes the corresponding generated
lint suppression. Product copy, introductory content, favicon and social card are
customized for Etch. Build/browser expectations use the resulting article routes.

## Repository paths and Pages

The repository-level [project workflow](../.github/workflows/project.yml) filters
changes to `website/**`, `docs/guides/**`, and its own workflow/composite action. Shell steps run in
`website`; dependency caching uses `website/package-lock.json`; build, download
and Pages upload paths point to `website/dist`. Dependabot's npm directory is
`/website`. The existing Python workflow is unchanged.

The canonical URL sets Astro's origin to `https://www.rm-industries.com` and its
base to `/etch`. Links, feeds, sitemap and static assets retain that base path.
There is deliberately no CNAME file: the organization website owns the shared
custom domain, and this repository publishes the `/etch/` project path.

Pages must use the GitHub Actions build source. The workflow deploys only a push
to `main`, after quality, browser, artifact and performance checks pass; pull
requests build and verify without deployment. No live deployment is claimed by
this bootstrap PR. Check the post-deployment smoke job after merging.
